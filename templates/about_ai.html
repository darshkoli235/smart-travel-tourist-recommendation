This project recommends trips with a small knowledge base and IF–THEN rules. No machine learning and no external AI service—just clear rules you can read and explain.

01
The knowledge base

Ten places, described with simple facts.

Each destination has an estimated starting budget, a suggested number of days and one or more types, like nature, beach or culture. These facts are stored in knowledge_base.py.

02
Forward chaining

Start with your facts. Apply the rules.

The program starts with your budget, trip length and preferred destination type. It checks all three against each place and puts the places with the most matches first.

IF your budget covers a place's estimated starting cost THEN its budget rule matches.
IF your trip length fits the suggested visit THEN its duration rule matches.
IF a place fits your preferred type THEN its destination-type rule matches.
03
Backward chaining

Start with a recommendation. Trace back why.

When you open “Why Recommended?”, the program starts with the question “Why is this place in the top three?” It works backwards: it checks the rules that could support the answer, then checks your original preferences.

If at least two rules match, the place is marked as a strong match. If there are fewer, the system explains that it was included as one of the three highest-ranked options.

A note about the estimates

Destination costs are sample values for a college project—not live prices. They represent a rough stay, meals and local travel estimate for one person, excluding travel to the destination.
